## Remaining gates

Protected payload storage currently uses an existing private 0700 directory outside the application checkout, immutable 0600 files, fsync and SHA-256 checks. It does not provide deployed encryption, retention purge, protected shared web/worker mounting, or Portal authorization for student payloads. A local environment flag permits synthetic fixtures only; there is no student-data activation flag. The current Compose web has no audit mount or model access, so its task endpoints fail closed.

The synthetic controlled-file library now accepts private named roots and actor grants, reads bounded UTF-8 text from authorized input folders, stages one exclusive output bundle per audited write attempt in a separate private root, and records file tool attempts through the protected task audit. Bundle content and manifest are one atomic file; a failed audit attempts to remove its staged bundle. No staged bundle is a published job artifact. Policy hashes change with the protected root/grant configuration. Generic chat tools remain denied even if file grants exist; no chat/Office workflow invokes the file library yet because that requires an approved plan-bound school tool surface. The adapter is not a qualified NAS mount or real student-data activation path. Per-job aggregate quotas, promotion/crash-orphan reconciliation, OS read-only mounts, separate service identities, shared protected storage, Portal class-summary contract, scoped PostgreSQL vector queries and egress isolation remain gates. Do not enter real student data in chat or synthetic tests. Never use a public/static directory as `AGENTOS_AUDIT_ROOT`.
